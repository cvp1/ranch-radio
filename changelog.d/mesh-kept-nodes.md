### Changed

- **Mesh: the node list keeps every node the station has heard.** A Meshtastic node's own list is short (80 nodes on an nRF52 board) and the bridge's starts again from it at every connect, so "known" fell back to 80-odd however long the station had listened: one node here had 380 names on record and 90 nodes listed, about half of what a phone app showed for a node beside it. The station now keeps a node the radio drops as it last was (`~/.local/state/radio-remote/mesh-nodes.json`, one file per node, up to 1000, the longest unheard going first): it stays in the list, dimmed, with its last heard, hops and position, counts in "known" and "heard today", and goes back to the radio's list when the radio next lists it. The count's tooltip says how many are the radio's own. A kept node's card says so; Remove forgets it. Kept nodes also show while the radio is not connected.
